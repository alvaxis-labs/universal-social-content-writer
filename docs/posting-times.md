# Suggested posting times

Read this guide for Posting Time Mode or a complete content package. Suggest when a person
could publish the content on X/Twitter or Facebook. Do not create scheduled posts, reminders,
or automations. Do not describe a suggested time as booked, approved, or published.

## Use the audience's context

Use the target audience's location and time zone, platform, campaign dates, and any existing
client schedule. The agent's or account owner's local time is not automatically the audience's
time. Check the relevant baseline or brief first; read only the necessary Sheet section if missing.

If a time zone is unknown, ask one specific question when it materially affects the task.
You can still finish the copy and visual prompt. For a provisional timing suggestion, write
“audience local time; time zone unconfirmed” and state the assumption. Do not pretend to have
converted it. For a multi-region audience, name the priority region or suggest separately
labeled regional windows instead of concealing the tradeoff in one global time.

## Evidence order

1. Respect fixed client launch times, embargoes, deadlines, and approved slots. Flag conflicts
   rather than moving the schedule yourself. A fixed time is a constraint, not evidence of peak engagement.
2. Prefer recent, relevant account data: audience activity and comparable post results for
   that platform, audience, objective, and period. Record the reporting period and time zone.
   Compare rates and reach as available, and distinguish paid from organic results. A single
   successful post does not establish a best hour.
3. Without suitable account data, propose a practical test window based on the audience's
   likely routine and the content's purpose. Label it “test hypothesis; no account analytics.”
   Explain the assumption. Do not delay ordinary work to demand analytics.
4. General industry studies are optional secondary context. If using one, research a current
   source and cite its date, platform, sample context, and limitations. Never present a generic
   benchmark as the account's proven best time. External timing claims follow SKILL.md's
   verification rules; a clearly labeled creative test hypothesis needs no invented benchmark.

## Suggest useful hours

Give one primary time or window per requested platform and an optional alternative when it
would support a useful test. State the day/date if known; for an undated brief, propose a day
and label it as a suggestion. Use 24-hour time and an explicit region/time-zone name. For a
dated recommendation, account for daylight saving when applicable; verify conversions before
providing a second time zone. Avoid unnecessary minute-level precision without a real constraint.

Do not automatically reuse the same hours for X and Facebook. Base each on its available
account evidence or label the separate assumptions. Never recommend a past time for an
upcoming post. Check that the suggestion leaves enough time for review and visual creation.
For time-sensitive announcements, relevance and the approved launch time may matter more
than a generic engagement window.

## Output format

**Suggested posting time:** day/date, hour or window, audience time zone.
**Basis:** account evidence, client constraint, or test hypothesis.
**Why:** a brief explanation tied to the audience and post objective.
**Alternative / next test:** only if useful.

Illustrative example, not a universal recommendation:

> Suggested posting time: Tuesday, 12:00–13:00, Asia/Ho_Chi_Minh (UTC+07:00).
> Basis: test hypothesis; no account analytics supplied.
> Why: test a lunchtime window for an audience assumed to work daytime office hours in Vietnam.
> Alternative: compare with a Thursday 18:00–19:00 window using similar posts and the same
> measurement period. Revisit the suggestion after several comparable posts.

Use the post's actual objective when evaluating results, such as link clicks, meaningful
replies, or leads. Do not invent performance improvements or attribute them to timing alone.
In downloadable workbooks, use Content Calendar’s Suggested date, Suggested time, Time zone and Timing basis fields. Keep client-approved dates/times separate and preserve them. For the optional connected Google Sheets route, use agent-owned Draft notes and preserve Date / Slot.
